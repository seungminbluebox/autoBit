# 잠긴 실전 연결 운영 안내

이 릴리스는 실전 운용을 허용하지 않습니다. `autobit.live` 연결 코드는 있으나
고정 guard가 자격증명 접근·서명·인증 HTTP·실전 원장 생성/변경 전에 실패합니다.
CLI, 환경변수, UI의 활성화 스위치는 없습니다. 실제 계정 조회, order-test,
주문/취소, 키 등록/탐색을 이 안내의 검증 단계로 수행하지 마십시오.
잠금 해제는 별도 명시적 승인과 검토된 코드 변경이 필요한 후속 작업입니다.

## 안전하게 확인하기

저장소 루트의 Python 환경에서 다음 예시는 키나 네트워크 없이 잠금만 확인합니다.

```python
from autobit.live.guard import LiveTradingLockedError, require_live_authorization

try:
    require_live_authorization()
except LiveTradingLockedError:
    print('Live trading is locked; paper and backtest remain available.')
```

```powershell
& ".\.venv\Scripts\python.exe" -m autobit.cli --help
& ".\.venv\Scripts\python.exe" -m autobit.cli paper-status --db ".\data\paper\paper.sqlite3"
```

도움말은 고정 잠금을 명시하고 live 모듈/인증 정보를 로드하지 않습니다. 기존
`data-download`, `data-quality`, `backtest`, `walk-forward`, `paper-once`,
`paper-run`, `paper-status` 일곱 명령은 유지됩니다. `paper-status`는 모의 원장을
읽을 뿐 실전 상태 조회가 아닙니다. 실제 모의 실행 절차는
[모의매매 runbook](../paper-trading-runbook.md)을 따릅니다.

## 한곳의 정책 변경과 적용 시점

진입·청산 우선순위·다음 손절·수량 판단의 소유자는
`src/autobit/core/engine.py`의 `StrategyEngine`입니다. 누적 위험 상태는
`src/autobit/core/risk_state.py`, 위험 제한은 `src/autobit/risk/breakers.py`,
전략 조건/손절 수식은 `src/autobit/strategy/donchian_trend.py`, 수량 수식은
`src/autobit/risk/position_sizer.py`에서 공통으로 사용됩니다. 파라미터는
`src/autobit/config.py`와 각 실행에 전달하는 설정이 기준입니다. 따라서
"한곳"은 공유 정책 소유권을 뜻하며 모든 수식이 단일 파일에 있다는 뜻은 아닙니다.
어댑터에 정책 조건문이나 수치를 복제하지 마십시오. 위험 설정은 현재 승인 수치와
다르면 fail-closed하므로 임의 파라미터를 운영 튜닝 스위치로 취급하지 마십시오.

변경은 **같은 코드 버전과 일치하는 전략/위험 설정으로 다음 실행**할 때 세 경로에
반영됩니다. 실행 중 프로세스의 hot reload, 자동 배포, 원격 프로세스 갱신은 없습니다.
기존 프로세스 종료와 다음 실행 사이 코드 버전·설정·원장 경로를 기록하십시오.
잠긴 live 레이어는 정책을 바꿔도 계속 잠깁니다.

과거 불변 이벤트를 새 정책으로 재작성하지 않습니다. paper risk v1은 엄격한
기존 증거 검증을 거쳐 읽고 새 판단은 v2로 기록합니다. v2 뒤의 v1 다운그레이드와
알 수 없는 버전은 거부합니다. v1에 없던 변동성/전환 전 입력을 추측해 과거 모든
판단을 완전히 재계산할 수 있다고 주장하지 않습니다. 기존 진입의 ATR 배수와
체결 사실은 그 진입의 기록을 유지합니다. 과거 정책을 새 주문에 선택하는 옵션은 없습니다.

## 세 모드 비교: 판단과 체결을 분리

| 경로 | 자금/수량 | 실행 증거와 시각 |
| --- | --- | --- |
| Backtrader | 설정된 시뮬레이션 자산(기본100) | 다음 봉 시가, 봉내 손절, 모사 비용/부분 체결 |
| PaperService | 최초100의 정규화 자산, 모의 BTC | PaperBroker와 불변 SQLite 이벤트, 기존 논리 봉 라벨 |
| LiveService | 거래소 응답의 실제 KRW/BTC | durable identifier, 실제 주문 조회/누적 체결/수수료/체결시각; 현재 잠금 |

인수 테스트는 동일한 수작업 확인 확정 지표를 실제 세 어댑터에 전달합니다.
paper 자산100을 억지로 늘리지 않습니다. 오프라인 mock live의 실제 단위 잔고는
1,000,000 KRW이며 명시적 양수 배율10000을 사용합니다. 비교할 때만 live 현금·자산·
손익·BTC수량을10000으로 나눕니다. 가격·ATR·손절·위험 비율·사유는 변환하지 않습니다.
이는 단위 비교이지 normalized100 원장을 실제100 KRW로 표시하는 허가가 아닙니다.
실제100 KRW 계정 자체는 가능하지만 거래소 최소주문금액 때문에 주문하지 못할 수 있습니다.

테스트의 비용0은 공유 수량 수식을 분리하기 위한 일치된 실험 설정이며 실제 거래소의
수수료가0이라는 주장이 아닙니다. mock 주문도 KRW/BTC 원단위 잔고·최소금액 검사를
통과해야 합니다. 기본 운영 비용은 편도 수수료0.05%와 슬리피지0.05%입니다.
예: 자산100, 진입100, ATR2, 위험2%이면 최초손절95와 수량0.4입니다.
고점112이면 다음손절106(112−3×2)이며 현재 봉의 활성손절95를 소급 변경하지 않습니다.
공통 수량 반환값을 반으로 바꾸는 테스트는 세 실제 주문 경로가0.2를 따르는지 확인합니다.
수량/금액의 부동소수 연산 비교는 상대1e-11·절대1e-12 오차를 허용하며
방향·사유·위험 비율·손절은 정확히 비교합니다. 체결 일치나 수익률 일치를 보장하지 않습니다.

일반 주문도 미확정 의도가 존재하는 동안 live 건강 상태를 정지시킵니다. 테스트는
실제 mock 조회 성공3회와 정상 완료 사이클로 복구를 진행하며, 최초 체결 뒤의
완료 사이클에는 `health_recovery_reduced`가 남음을 따로 검증합니다. 비교는 정상
진입·복구 후 추적손절·종가 청산처럼 정규화한 정책 입력이 일치하는 행에서 수행하고,
이 일시적인 live 건강 상태까지 paper/backtest와 동일하다고 주장하지 않습니다.

live `row['timestamp']`는 시간대가 있는 UTC 4시간 정렬 **봉 시작**입니다.
완료는 시작+4시간, `RiskObservation.now`는 별도의 관측 cutoff이며
완료≤cutoff≤clock이어야 합니다. paper/backtest는 기존 논리 시작 라벨을 유지합니다.
인수 비교의 live cutoff가 완료와 같을 때 위험 기한 라벨 비교만4시간 차이를 정규화합니다.
실제 체결시각은 바꾸지 않습니다. live 주문 생성시각의 문서화된 초 단위 정밀도와
실제 체결의 소수초는 별개입니다. 오래된/미완료/반복 봉은 신규 역사 주문을 정당화하지 않습니다.
보유 봉수는 실제 진입이 속한 봉을0으로 하여 현재 완료 봉의 **시작** bucket에서
진입 봉 bucket을 뺍니다. 완료 cutoff를 사용하여1봉을 더하지 않습니다. 비교할 때
Backtrader의 직전 고점과 paper/live의 이미 반영된 고점은 공통 엔진의
`max(position.high_water, row['high'])`로 동일한 유효 고점을 확인하며, 원시 입력 필드가
항상 같은 단계에 있다고 주장하지 않습니다. 시각·고점·보유량은 실제 체결 사실을 보존합니다.

진입은 누적 매수의 실제 첫 체결시각을 유지하며, 마지막 체결시각은 청산용으로
별도 보존합니다. 조정 후 진입시각이 공급된 봉 끝 이상이면 그 봉의 OHLC는
보유 이후 관측이 아니므로 `DEFERRED_PRE_ENTRY_CANDLE`로 유보합니다. 고점·손절·
청산·평가자산·위험 이력을 진행하지 않고 다음 적합한 봉에서 자동 재개합니다.
봉 끝과 같은 시각의 진입은 다음 봉에 속합니다. 유보는 건강 정지나 주문이 아니며,
별도 실제 가격 관측에 의한 보호와 기존 사실은 유지됩니다.

15% 낙폭 사건은72시간 대기를 한 번 시작합니다. 정확히72시간부터 정상 상태라면
과거 낙폭만으로 다시 정지시키지 않고 축소 재개합니다. 낙폭10% 이상은 위험0.25%·
상한15%, 5% 이상은0.5%·30%, 0% 초과는1%·50%, 이전 최고자산 회복 시2%·70%입니다.
독립 일간/주간/연속손실/변동성/건강 제한 중 더 엄격한 조건이 우선합니다.
예를 들어100→84 현금의72시간 회복에도 주간 손실 축소가 남으면0.125%·7.5%이고,
변동성 정지까지 활성화되면 진입하지 않습니다. 최고자산100과 실제 손실은 보존합니다.

## 미확정 주문·재시작·장애

승인된 미래 연결에서 사용할 계약은 [상세 연결 계약](../locked-live-contract.md)에 있습니다.
현재 사용자가 실제 조회로 실험하는 절차는 제공하지 않습니다.

주문 의도와 고유 identifier는 전송 전에 live 전용 원장에 저장합니다.
응답 timeout/불명확/프로세스 재시작 시 같은 identifier로 조회하여 조정하며
맹목적으로 POST를 재시도하거나 새 identifier로 주문하지 않습니다. not-found도
미확정 상태이며 원장을 지우거나 pending을 수동으로 지워 해결하지 않습니다.
부분 체결·취소 응답 뒤에도 실제 누적 조회 사실을 사용하고 미확정 주문이 남으면
새 진입을 막습니다. 기존 SELL 의도는 중복 발행하지 않습니다.

미확정 기간에는 canonical 위험 cutoff와 완료 cursor를 동결해 뒤늦게 확인한 실제
청산시각을 과거 cutoff 뒤에 정직하게 반영할 수 있게 합니다. 완료 봉에서 확인한
보유기간·고점·보호 진행은 별도 `completed_bar_at`(봉 시작)와 fingerprint로
저장하며 canonical 위험 기록을 대신하지 않습니다. 반복 봉은 조정/현재 건강 확인만
하고 새 신호 주문이나 회복 봉 카운트를 추가하지 않습니다.

원장 불일치, 관리되지 않은 BTC, 알 수 없는 주문은 조용히 초기화하지 말고 증거와
오류를 보존하여 검토하십시오. 로그/오류/원장에 key, secret, JWT를 넣지 마십시오.
동시 실행 방지는 로컬 단일 호스트·정규 SQLite 경로의 소유권 계약입니다.
클라우드 동기화 폴더/공유 파일시스템/분산 잠금에 대한 운용 보장이 아닙니다.
실전 원장은 paper와 분리하며 파일 전체 악의적 rollback을 암호학적으로 막지는 않습니다.

## 검증 범위와 미완료 작업

오프라인 테스트만 guard를 테스트 범위에서 패치하고 가짜 인증 정보와
`httpx.MockTransport`를 주입합니다. 이것은 프로덕션 스위치나 실행 예제가 아닙니다.
실제 개인 요청/주문/취소, 실시간 가격 feed/daemon, 거래소 네이티브 stop은 제공하거나
검증하지 않았습니다. live 보호는 관측 가격과 활성손절을 비교하는 서비스 계약이며
관측이 끊긴 상태의 실시간 보호를 보장하지 않습니다.

최근7년 실제 성과 검증, 최소2주·30회 모의 관찰 완료, 투자 적합성, 실전 준비 완료를
이 구현이나 인수 테스트로 주장하지 않습니다. 테스트 로그의 코드 버전·명령·출력·
종료코드와 실제 운영/성과 증거를 분리하여 보관하십시오. 병합·푸시·배포·활성화는
이 작업의 결과가 아닙니다.
