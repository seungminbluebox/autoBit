## 3. 전략 가설과 실패 조건

### 3.1 검증 가능한 가설

BTC의 큰 상승 움직임은 군중 행동, 정보 확산 지연, 포지션 추종으로 인해 일정 기간 지속될 수 있다. 장기 상승 필터 위에서 최근 50개 확정봉의 최고가를 돌파한 움직임에 참여하고, 최근 20개 확정봉의 최저가 이탈과 변동성 기반 손절로 하방을 제한하면 현금 보유와 큰 추세 포착의 결합이 비용 반영 후 buy-and-hold 대비 더 나은 수익 대비 낙폭을 만들 수 있다는 가설을 검증한다.

### 3.2 예상 실패 국면

- 방향 없이 위아래로 흔들리는 횡보장
- 돌파 직후 빠르게 되돌아오는 가짜 돌파 구간
- 4시간봉 사이에 큰 갭 또는 급락이 발생하는 구간
- 비용과 슬리피지가 전략의 작은 기대값을 소진하는 구간
- 과거 7년과 다른 시장 구조로 추세 지속성이 약해진 구간

### 3.3 폐기 논리

OOS 손익, 위험 조정 성과, 과최적화 지표, fold 안정성이 합격 기준을 충족하지 못하면 파라미터를 계속 추가해 살리지 않는다. 재검토 범위를 벗어난 결과는 전략을 폐기한다.

## 4. 기계적으로 테스트 가능한 전략 규칙

모든 지표와 신호는 UTC 기준으로 끝난 4시간봉 `t`에서만 계산한다. 진행 중인 봉은 입력에 포함하지 않는다.

### 4.1 지표

- 장기 추세: `EMA(close, 200)`
- 진입 채널: 현재 봉을 제외한 직전 50봉 최고가
- 추세 청산 채널: 현재 봉을 제외한 직전 20봉 최저가
- 변동성: `ATR(14)`

RSI, MACD, ADX, 거래량 확인 지표는 v1.0에 넣지 않는다. 지표 수를 늘려 과거 성과를 맞추는 것을 금지한다.

### 4.2 진입

아래 조건을 모두 만족할 때 `ENTRY_SIGNAL`을 생성한다.

```text
entry_high[t] = max(high[t-50], ..., high[t-1])
entry_high[t-1] = max(high[t-51], ..., high[t-2])

close[t] > entry_high[t]
AND close[t] > EMA200[t]
AND close[t-1] <= entry_high[t-1]
AND 모든 필수 지표가 유효함
AND 데이터 품질 필터가 통과됨
AND 리스크 엔진이 신규 진입을 허용함
AND 상태가 FLAT임
```

신호는 봉 `t` 종가가 확정된 뒤 생성하며 시장가 진입은 기본적으로 봉 `t+1` 시가에 체결한다.

### 4.3 초기 손절

실제 체결가를 `entry_price`, 진입 신호 봉의 ATR을 `entry_atr`로 정의한다.

```text
initial_stop = entry_price - 2.5 * entry_atr
R = entry_price - initial_stop
```

`R <= 0`, ATR이 유효하지 않음, 손절가가 0 이하인 경우에는 주문량을 0으로 처리한다.

### 4.4 수익 보호와 추적 손절

고정 목표가로 수익 상단을 제한하지 않는다. 대신 고가가 `entry_price + 2R`에 도달한 뒤부터 수익 보호를 활성화한다.

확정봉 `t`가 끝날 때 다음 봉에 적용할 손절가를 갱신한다.

```text
next_trailing_stop = max(
    previous_stop,
    entry_price,
    highest_high_since_entry_through_t - 3.0 * ATR14[t]
)
```

새 손절가는 다음 봉부터 효력이 있다. 같은 봉의 고가로 손절가를 높인 뒤 그 봉의 저가에 소급 적용하지 않는다.

### 4.5 추세 청산

```text
exit_low[t] = min(low[t-20], ..., low[t-1])
close[t] < exit_low[t]
```

조건이 확정된 뒤 봉 `t+1` 시가에 시장가 청산한다.

### 4.6 시간 기반 청산

- 정체 청산: 진입 후 60봉, 즉 10일 동안 `highest_high_since_entry < entry_price + 1R`이면 다음 봉 시가에 청산한다.
- 최장 보유: 진입 후 1,095봉, 약 6개월이 되면 다음 봉 시가에 청산한다.

보유기간은 고정하지 않되, 움직이지 않는 포지션과 무기한 상태 유지를 막는다.

### 4.7 청산 우선순위

1. 기존 봉 시작 전에 활성화된 하드 스톱 또는 추적 손절
2. 데이터·리스크 엔진의 강제 청산
3. 확정봉 추세 청산
4. 정체 청산
5. 최장 보유 청산

같은 4시간봉에서 기존 손절가와 `+2R` 활성화 가격이 모두 닿은 경우, 더 낮은 시간봉 데이터가 없으면 손절이 먼저 발생한 것으로 처리한다. 시가가 손절가 아래이면 손절가가 아니라 더 불리한 시가에 청산 슬리피지를 적용한다.

## 6. 지표 계산과 룩어헤드 방지

- 정제가 끝난 데이터에만 지표를 계산한다.
- 최초 또는 장기 공백 이후 600개의 정상봉은 워밍업으로 제외한다.
- 모든 필수 지표 중 하나라도 NaN이면 신호를 생성하지 않는다.
- Donchian 상단과 하단은 반드시 현재 봉을 제외하도록 한 봉 이동한다.
- 신호를 만드는 봉의 종가로 같은 종가에 체결하지 않는다.
- 기본 체결 시점은 다음 봉 시가다.
- 전체 데이터로 계산한 과거 지표와 그 시점까지만 잘라 계산한 지표가 일치하는지 회귀 테스트한다.
- 기본 파라미터는 설정으로 분리하지만 OOS를 본 뒤 변경하지 않는다.

## 7. 상태 머신과 주문 수명주기

### 7.1 전략 상태

```text
FLAT
  -> ENTRY_PENDING
  -> LONG
  -> EXIT_PENDING
  -> FLAT
```

위험 또는 시스템 제한이 발동하면 `HALTED`로 이동한다. `HALTED`는 영구 정지가 아니라 자동 점검과 냉각 뒤 축소된 크기로 자동 복귀할 수 있는 안전 상태다.

### 7.2 주문 상태

- `CREATED`
- `SUBMITTED`
- `ACCEPTED`
- `PARTIAL`
- `COMPLETED`
- `CANCELED`
- `EXPIRED`
- `INSUFFICIENT_CASH`
- `REJECTED`

처리 중 주문 ID가 있으면 동일 방향의 새 주문을 만들지 않는다. 모든 주문은 고유한 멱등성 키를 가진다.

### 7.3 잔고와 수량 제한

- 매수 비용과 수수료의 합은 가용 현금을 넘을 수 없다.
- 매도 수량은 보유 BTC를 넘을 수 없다.
- 추가 진입, 물타기, 피라미딩을 금지한다.
- 부분체결은 실제 체결 수량만 포지션으로 인정한다.
- 부분체결 또는 응답 오류 뒤에는 주문 상태와 잔고를 대조하기 전 재주문하지 않는다.
- 진입 부분체결은 체결분만 `LONG`으로 인정하고 잔여분은 같은 봉이 끝날 때 취소하며 자동 재주문하지 않는다.
- 청산 부분체결은 `EXIT_PENDING`을 유지하고 잔여 보유량을 다음 봉 시가에 한 번만 다시 청산한다.
- 진입 주문이 다음 봉에서 전혀 체결되지 않으면 주문을 취소하고 `FLAT`으로 돌아가며, 새로운 진입 신호가 생기기 전에는 재주문하지 않는다.

## 8. 포지션 크기

현재 리스크 상태가 허용하는 거래당 위험률을 `risk_rate`로 정의한다.

```text
risk_amount = account_equity * risk_rate
```

예상 시장가 진입과 손절의 비용을 포함한다.

```text
effective_loss_per_btc
  = expected_entry_fill
  - expected_stop_fill
  + entry_fee_per_btc
  + exit_fee_per_btc
```

```text
qty_fixed = risk_amount / effective_loss_per_btc
```

변동성이 평소보다 높을 때만 추가 축소한다.

```text
current_atr_pct = ATR14 / close
baseline_atr_pct = 과거 252개 확정봉 ATR 비율의 중앙값
vol_multiplier = min(1, baseline_atr_pct / current_atr_pct)
qty_vol = qty_fixed * vol_multiplier
```

그 밖의 상한은 다음과 같다.

```text
qty_exposure = account_equity * current_exposure_cap / expected_entry_fill
qty_cash = available_cash / (expected_entry_fill * (1 + entry_fee_rate))
```

최종 수량은 아래 값 중 가장 작은 수량을 거래소 허용 정밀도에 맞춰 아래 방향으로 절삭한다.

```text
final_qty = floor_to_exchange_precision(
    min(qty_fixed, qty_vol, qty_exposure, qty_cash)
)
```

손절 거리 0 이하, ATR 비정상, 데이터 부족, 수량 비양수, KRW 모드에서 최소 주문금액 미달이면 주문량은 0이다.

v1.0에서는 Kelly를 사용하지 않는다. OOS 거래 100회 이상과 충분한 모의매매 기록이 생겨도 별도 연구 후보로만 계산하며 상한은 0.25 Kelly다.

## 9. 자동 리스크 축소와 자동 복구

### 9.1 일반 낙폭 단계

| 고점 대비 낙폭 | 거래당 위험 | BTC 투자 상한 |
|---|---:|---:|
| 0% 이상 5% 미만 | 2.0% | 70% |
| 5% 이상 10% 미만 | 1.0% | 50% |
| 10% 이상 15% 미만 | 0.5% | 30% |
| 15% 이상 | 신규 진입 일시 중단 | 기존 포지션 정리 |

### 9.2 15% 낙폭 자동 복구

- 기존 포지션을 체계적으로 청산하고 72시간 냉각한다.
- 데이터와 시스템 상태가 정상이면 사람 승인 없이 자동 재개한다.
- 재개 위험은 0.25%, BTC 투자 상한은 15%다.
- 회복 모드에서 낙폭 10% 미만이면 위험 0.5%, 상한 30%다.
- 낙폭 5% 미만이면 위험 1.0%, 상한 50%다.
- 이전 최고자산을 회복하면 위험 2.0%, 상한 70%로 복귀한다.

일반 낙폭 단계와 복구 단계가 겹치면 복구 단계의 더 작은 크기를 적용한다.

### 9.3 손실 제한

- UTC 하루 손실 4%: 24시간 신규 진입 중단 후 축소 재개
- 최근 7일 손실 5%: 거래 위험과 투자 상한 절반
- 최근 7일 손실 7%: 최소 48시간 신규 진입 중단 후 축소 재개
- 3회 연속 손실: 거래 위험과 투자 상한 절반
- 5회 연속 손실: 48시간 신규 진입 중단
- 냉각 뒤 절반 크기로 재개하고 순이익 거래 2회 뒤 해당 연속 손실 제한을 해제

### 9.4 변동성 제한

`current_atr_pct / baseline_atr_pct`가 2를 넘으면 위험과 투자 상한을 절반으로 줄인다. 3을 넘으면 신규 진입을 중단한다. 비율이 1.5 이하인 확정봉이 3개 연속 나타나면 자동 재개한다.

### 9.5 시스템 제한

아래 조건에서 `HALTED`로 전환한다.

- API 요청 3회 연속 실패
- 끝나야 할 4시간봉이 종료 후 10분이 지나도 없음
- 타임스탬프 역전 또는 응답 구조 오류
- 주문 상태를 확인할 수 없음
- 저장된 포지션과 모의 잔고가 불일치
- 예상가와 체결가가 5% 이상 차이

자동 복구 작업은 지수 백오프 재시도, 주문 이벤트 재생, 잔고 대조, 데이터 품질 재검사 순서로 수행한다. 정상 API 응답 3회, 미확인 주문 0건, 잔고 일치, 데이터 정상 조건이 모두 충족되면 축소 크기로 자동 재개한다. 여러 제한이 동시에 활성화되면 가장 엄격한 제한을 적용한다.

## 10. Backtrader 백테스트

- `cheat_on_open=False`, `cheat_on_close=False`
- 확정봉 신호는 다음 봉 시가에 체결
- 초기자산 100
- 현물 롱 전용, 레버리지와 음수 현금 금지
- 기본 수수료 편도 0.05%
- 기본 슬리피지 편도 0.05%
- 스트레스 슬리피지 편도 0.10%, 0.20%
- 비용 0 시나리오도 별도 실행
- 수수료와 슬리피지를 중복 계산하지 않음
- 신호, 주문, 체결, 수수료, 슬리피지, 청산 원인, 실현·미실현 손익, 자산곡선 기록

OHLCV만으로 부분체결 순서를 알 수 없으므로 기본 백테스트는 정상 시장가 주문의 다음 봉 전량 체결을 가정한다. 주문 상태 머신은 부분체결을 지원한다. 스트레스 테스트에서는 진입 요청량의 50%만 다음 봉 시가에 체결하고 잔여분을 그 봉 끝에 취소한다. 청산 요청량의 50%만 체결되는 경우에는 남은 수량을 그다음 봉 시가에 추가 슬리피지를 적용해 한 번만 청산한다.

buy-and-hold는 각 평가 구간의 첫 거래 가능 시점에 정규화 자산 100%로 BTC를 매수하고 마지막 시점에 매도하는 비교 기준이다. 비용 0과 동일 비용 적용 결과를 모두 계산한다.

## 11. Walk-forward 검증

### 11.1 시간 분할

- 방식: 고정 길이 rolling window
- 학습·안정성 점검: 과거 2년
- embargo: 5일, 4시간봉 30개
- OOS 시험: 다음 3개월
- 이동 간격: 3개월
- 데이터: 실행 시점 기준 최근 7년
- 예상 fold 수: 실제 시작·종료 시각과 데이터 품질에 따라 약 20개

랜덤 K-fold와 무작위 train/test 분할을 금지한다. forward label은 사용하지 않는다. 학습 구간 끝에서 열린 포지션은 학습 성과 안에서 강제 정리하고 OOS로 넘기지 않는다. OOS는 `FLAT`, 미체결 주문 0건, 초기자산 100으로 시작한다. 지표 워밍업에는 OOS 시작 이전의 당시 이용 가능했던 과거 데이터만 사용한다.

### 11.2 파라미터 시도 수

사전 고정한 기본 조합과 한 번에 한 요소만 바꾼 8개 민감도 조합, 총 9개를 기록한다.

- EMA: 기본 200, 민감도 150과 250
- 진입 Donchian: 기본 50, 민감도 40과 60
- 청산 Donchian: 기본 20, 민감도 15와 25
- ATR 손절 배수: 기본 2.5, 민감도 2.0과 3.0
- ATR 기간: 14로 고정

민감도 조합은 강건성 진단용이며 OOS를 보고 기본 전략을 교체하지 않는다. 선택되지 않은 결과와 실패 결과도 모두 저장한다.

### 11.3 과최적화 진단

- 모든 9개 시도를 포함한 Deflated Sharpe Ratio
- 10개 연속 그룹 중 2개를 시험으로 선택하는 CPCV 45개 경로로 PBO 계산
- IS/OOS Sharpe 비율
- fold별 성과 분산
- 상승·하락·횡보 구간별 결과
- 한 fold의 전체 OOS 순수익 기여도

### 11.4 합격 기준

다음을 모두 만족해야 `PASS`다.

- 비용 반영 전체 OOS Sharpe > 1.0
- 비용 반영 Profit Factor > 1.5
- 최대 낙폭 <= 15%
- 전체 OOS 거래 수 >= 100
- DSR >= 0.95
- PBO < 0.30
- OOS fold의 60% 이상에서 비용 반영 기대값 > 0
- 한 fold가 전체 OOS 순수익의 50% 이상을 독점하지 않음
- IS/OOS Sharpe 비율 < 2.0
- 슬리피지 0.20% 스트레스에서도 계좌 생존 규칙 준수

거래 수가 100회 미만이면 다른 수치가 좋아도 `INSUFFICIENT_STATISTICS`다. DSR 0.80 이상 0.95 미만 또는 PBO 0.30 이상 0.50 미만이면 `REVIEW`다. OOS 순손실, Sharpe <= 0, Profit Factor <= 1, 최대 낙폭 > 15%, DSR < 0.50, PBO >= 0.50 중 하나라도 해당하면 `REJECT`다. PASS와 REJECT 사이의 결과는 원인과 함께 REVIEW로 분류하지만 OOS를 본 뒤 조건을 추가해 PASS로 바꾸지 않는다.

### 15.4 전체 인수 테스트

최근 7년 수집, 품질 보고서, 기본 백테스트, 비용 스트레스, buy-and-hold, Walk-forward, DSR/PBO, 최종 판정 보고서가 처음부터 끝까지 생성되어야 한다.

## 16. 모의매매 전환 체크리스트

- 데이터 품질 보고서가 치명 오류 없이 통과
- 기본 백테스트와 모든 단위·통합·회귀 테스트 통과
- Walk-forward 판정 PASS
- 정규화 모의 원장과 SQLite 재시작 복구 확인
- 자동 안전 대기와 자동 복구 장애 주입 테스트 통과
- 주문 중복 0건, 음수 현금 0건, 초과 매도 0건
- 최소 2주와 30회 거래를 모두 충족할 때까지 모의매매 지속
- 모의 성과가 OOS 기대 범위에서 25% 넘게 악화되면 원인 분석 전 단계 전환 금지
- 실주문 모듈과 API 키는 여전히 존재하지 않아야 함

## 17. 전략 생명주기

- 계속 검증: OOS PASS이고 모의매매가 OOS 기대 범위와 일치
- 재검토: 지표가 REVIEW 범위이거나 모의 성과가 OOS 대비 25% 넘게 악화
- 폐기: OOS REJECT, 전략 가설 붕괴, 비용 후 기대값 비양수, 최대 낙폭 위반이 반복됨
- 파라미터 변경은 새 전략 버전과 새 전체 검증으로 처리
- 실패 실험을 삭제하지 않음

## 18. 결정되지 않은 항목과 명시적 가정

다음 항목은 현재 단계에서 의도적으로 결정하지 않는다.

- 실제 KRW 운용자금
- 실주문 API 키, 권한, IP 허용 목록
- 실주문 브로커와 주문 재조정 정책
- 실제 계정의 주문 가능 정밀도와 이벤트 수수료
- 실주문 배포 환경과 운영 책임자

현재 설계의 가정은 다음과 같다.

- 정규화 자산 100은 비율 비교용이며 실제 최소 주문금액을 나타내지 않는다.
- 정상 KRW-BTC 시장가 주문은 기본 백테스트에서 다음 봉 시가 부근에 전량 체결될 수 있는 작은 주문으로 본다.
- OHLCV만으로 봉 내부 체결 순서를 알 수 없으므로 모호한 경우 최악 체결을 택한다.
- 업비트 정책은 변경될 수 있으므로 공식 출처와 확인 시각이 있는 버전 설정으로 관리한다.
- 7년 데이터로 거래 100회를 만들지 못하면 기준을 낮추지 않고 통계적으로 불충분하다고 판정한다.

## 19. 구현 승인 경계

이 문서의 승인은 구현 계획 작성을 허용한다. 실제 Python 소스 교체는 구현 계획을 검토한 뒤 사용자가 별도로 명시적으로 승인해야 한다. 실주문 연결은 그보다 더 뒤의 별도 승인 대상이다.
