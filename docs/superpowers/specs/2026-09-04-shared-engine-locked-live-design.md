# 공통 매매 엔진·자동 재개·잠긴 실전 연결 설계

작성일: 2026-09-04. 상태: 사용자 승인된 방향을 구현 계약으로 문서화. 구현 및 검증은 별도 작업 기록으로 추적한다.

## 1. 승인 범위와 완료의 의미

사용자는 전략 한곳을 수정하면 백테스트·모의매매·실전 매매에 함께 반영되는 구조와 15% 낙폭 후 자동 재개 수정을 승인했고, 문서 갱신 후 구현을 요청했다. 실전 연결 코드도 구현하되 이 작업에서는 실제 계정 조회, API 키 등록·탐색, 서명된 외부 요청, 주문 생성·취소, 실제 자금 사용을 하지 않는다. 배포·병합·푸시 역시 포함하지 않는다.

세 환경의 **동일한 입력에 대한 매매 판단**이 같아야 한다. 거래소 실제 체결과 과거 봉 기반 모사 체결은 다르므로 수익률·체결가 일치를 보장하지 않는다. 변경은 같은 코드 버전으로 다음 실행할 때 적용된다. 실행 중 임의 코드 교체나 자동 배포는 범위 밖이다.

잠긴 실전 연결 코드와 오프라인 테스트를 완료하는 것은 실전 운용 준비 완료 또는 투자 적합 판정을 뜻하지 않는다. 최근 7년 성과 검증과 모의 운용 관찰 결과는 실제 수행한 경우에만 보고한다.

## 2. 유지할 전략

기존 `2026-09-02-krw-btc-trend-system-design.md`가 전략 수치의 기준이다. KRW-BTC 현물, 단일 롱/현금, 확정 4시간봉, EMA200·Donchian50/20·ATR14, 정상봉 600개 준비, 정상 위험 2%·투자 상한 70%, 시장가 방식은 유지한다. 물타기·피라미딩·레버리지·공매도는 금지한다.

최초 손절은 실제 진입 체결가에서 진입 ATR의 2.5배 아래다. +2R 도달 후 추적 손절은 기존 손절·진입가·고점에서 ATR 3배 아래 중 최댓값이며 다음 봉부터 효력을 갖는다. +1R 미도달 60봉 정체 청산, 1095봉 최대 보유 청산을 유지한다. 비용·실제 시가 주문 한도·부분 체결·취소·중복 청산 방지 계약도 유지한다.

일간·주간·연속 손실·변동성·데이터 및 실행 상태 제약은 독립적으로 적용하고 가장 엄격한 제한이 우선한다. 건강하지 않은 상태에서 무조건 주문하도록 바꾸지 않는다. 정상화 조건을 충족하면 수동 리셋 없이 자동으로 다시 판단한다.

## 3. 공통 엔진과 실행 어댑터

`autobit/core`는 네트워크·파일·DB·Backtrader에 의존하지 않는 순수 판단 계층이다. 정규화된 확정봉/지표, 포지션 및 주문 상태, 현금/자산, 체결된 거래 결과, 건강 상태를 받아 다음 위험 상태와 주문 의도를 반환한다.

공통 소유: 진입 조건, 청산 우선순위, 최초·추적 손절, 정체·최대 보유 조건, 위험 상태 누적/쿨다운/회복, 위험 기반 수량 판단. 기존 지표·전략·수량 함수는 이 계층이 사용하는 단일 구현으로 유지한다. 어댑터에 같은 숫자와 조건문을 복제하지 않는다. 입력 행 변환이나 체결 사실에 따른 보유 봉수 계산은 실행 경계의 책임이다.

실행 소유: Backtrader의 과거 체결·수수료·주문 콜백, PaperBroker의 모사 체결 및 SQLite 원장, LiveService의 실제 체결 조회 및 주문 상태 조정. 세 어댑터가 같은 공통 엔진을 실제 호출해야 하며, 라이브가 모의 체결을 실제 체결로 기록해서는 안 된다.

공통 판단 출력은 매수·매도·대기, 사유, 허용 수량, 다음 손절, 위험 상태를 명시한다. 현재 유효 손절과 다음 봉 적용 손절의 시점을 구분한다. 미체결 주문이 있으면 새 진입을 중복 발행하지 않는다. 실제 체결가·잔고·최소 주문 제약은 주문 전 실행 경계에서도 검증한다.

## 4. 15% 낙폭 후 자동 재개

원인: 최고자산 100에서 자산 84로 청산한 뒤, 72시간이 지나도 낙폭이 15% 이상이라는 이유로 무기한 정지한다. 현금만 보유하면 낙폭을 줄일 기회가 없어 교착 상태가 된다.

새 규칙:

1. 새로운 15% 이상 낙폭 사건이면 강제 청산하고 72시간 대기 시작 시각을 한 번만 저장한다.
2. 72시간 이전에는 재진입하지 않는다. 정확히 72시간부터 다른 정지 조건이 없고 시스템이 정상이라면 낙폭이 여전히 15% 이상이어도 축소 재개한다.
3. 회복 단계는 낙폭 10% 이상에서 위험 0.25%·투자 상한 15%, 5% 이상에서 0.5%·30%, 0% 초과에서 1%·50%, 이전 최고자산 회복 시 정상 2%·70%다. 다른 축소 조건과 겹치면 더 엄격하게 적용한다.
4. 같은 회복 사건의 과거 낙폭만으로 72시간을 다시 시작하거나 회복 중 새 포지션을 매번 강제 청산하지 않는다. 이전 최고자산 회복 후 새로운 낙폭 사건은 다시 정지시킬 수 있다.
5. 최고자산을 낮추거나 손실 기록을 지워 회복한 것처럼 처리하지 않는다. 재시작·반복 봉 처리도 같은 결론이어야 한다.

기존 불변 원장은 지우거나 재작성하지 않는다. 기존 risk payload v1에는 변동성 비율과 일부 전환 전 상태가 없어 과거의 모든 판단을 정확히 재계산할 수 없다. 기존의 엄격한 스키마·이벤트 식별자·시각·투영·건강 증거 검증을 유지하고, 저장된 사실로 확인 가능한 모순을 거부한다. 누락된 입력을 추측하거나 이를 이유로 정상 기존 원장을 모두 거부하지 않는다. 새 결정은 v2로 기록하고 v2 이후 v1 다운그레이드와 알 수 없는 버전은 거부한다. 기존 정상 원장으로 시작해 새 정책으로 전환하는 테스트가 필수다. 과거 정책을 새 매매에 선택하는 옵션이나 사용하지 않는 구버전 평가기 복제는 만들지 않는다. 과거 canonical 위험 판단의 완전한 재계산은 기존 기록만으로 보장하지 못한다.

## 5. 실전 연결은 구현하되 잠금 유지

실전 모듈은 공식 업비트 API의 계정/주문 가능 정보, 시장가 매수·매도, 단건 주문 확인·취소를 구현한다. JWT HS512·고유 nonce·순서 보존 및 비이스케이프 쿼리 SHA512 규칙을 따른다. 시장가 매수는 KRW 총액(`ord_type=price`)이고 시장가 매도는 BTC 수량(`ord_type=market`)이다. 인증 정보와 토큰은 로그·오류 메시지·원장에 저장하지 않는다.

이번 릴리스의 실전 진입점은 자격증명 접근·서명·인증 HTTP 요청 이전에 고정 잠금으로 실패한다. CLI 인자·환경 변수·UI toggle로 잠금을 해제하지 않는다. 단위/통합 테스트에서만 guard를 패치하고 `httpx.MockTransport`를 주입하여 실제 코드 경로를 오프라인으로 검증한다. 프로덕션에 테스트 우회 스위치를 제공하지 않는다. 이후 실전 활성화는 별도 명시적 승인과 검토된 변경이다.

HTTP 목적지는 `https://api.upbit.com`과 검토된 경로만 허용한다. TLS 검증을 사용하고 redirect 및 환경 proxy 상속을 막는다. 응답은 상태·수량·수수료·가격·식별자·마켓·방향을 검증한다. 주문 가능 최소 금액과 실제 KRW/BTC 잔고는 승인된 실행 시 거래소 정보로 확인한다. 정규화 자산 100을 실제 100 KRW로 오인하지 않는다.

전송 전에 고유 주문 identifier와 의도를 라이브 전용 영속 원장에 기록한다. 시간 초과·응답 불명확·재시작 시 동일 identifier로 조회하여 조정하고 맹목적으로 재전송하거나 새 identifier로 중복 주문하지 않는다. 미확정 주문은 해결 전 신규 주문을 막는다. 부분 체결·실제 수수료·취소 후 잔여·0 체결·보유량 초과 매도 방지를 검증한다. 단일 실행자/원자적 원장 갱신으로 동시 중복 주문을 막는다.

실제 시장가 체결을 과거 다음 봉 시가로 기록하지 않는다. 실시간 보호 손절은 관측된 가격으로 공통 손절 정책을 적용해 매도 의도를 만들며, 거래소가 지원하지 않는 네이티브 stop 주문을 있다고 가정하지 않는다. 영구 잠금 상태에서 모의 운용이나 공개 데이터 수집은 계속 독립적으로 사용할 수 있다.

## 6. 기존 안전성과 호환성

PaperService의 불변 이벤트 재생·원장 거래·실행 lease·장기 보유 진입 맥락·건강 증거 영속화·알림 at-most-once·공개 데이터 재시도 및 정상화 조건을 유지한다. Backtrader의 next-open/next-bar 인과성과 부분 체결/취소 처리를 유지한다.

기존 '실전 코드가 전혀 없음' 정적 검사는 승인된 변경에 맞게 '공통/백테스트/모의 계층에서 개인 API 경로가 없음 + 검토된 live 경계와 고정 잠금' 검사로 바꾼다. 전체 패키지를 검사에서 빼거나 임의 URL/동적 호출을 전역 허용하지 않는다. 기존 우회 공격 테스트와 추가 인증 경계·비밀 유출·잠금 테스트를 함께 통과해야 한다.

## 7. 인수 기준

- 경계 시각, 반복 처리, 재시작, 다른 정지 동시 적용, 최고자산 불변, v1→v2 호환성 및 변조 거부 회귀 테스트.
- 같은 수작업 확인 입력의 세 환경 주문 의도 비교; 공통 정책 하나를 바꾸면 세 환경이 함께 달라지는 테스트. 단순 import 확인만으로 대체하지 않는다.
- 실제 Backtrader/PaperService가 공통 엔진을 호출하고 중복 전략 분기가 제거된 정적/행동 검증.
- 시장가 요청·서명·실패/재조정·부분 체결·취소·재시작·동시 실행·잔고/최소 주문·건강 악화·잠금의 오프라인 검증.
- 기존 회귀 및 최종 전체 테스트. 테스트별 코드 버전·명령·출력·종료 코드를 남긴다. 실전 실행 및 성과 검증 미실시를 명확히 구분한다.
